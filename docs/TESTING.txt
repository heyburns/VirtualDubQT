Bugfix checkpoints and regression checks
=======================================

The standalone codec troubleshooting suite is not part of these checks.
All generated source files, failure fixtures, and exports are temporary. The
offscreen controller test also isolates its settings and queue from user data.

Build and run (presets require CMake 3.21 or newer):

  cmake --preset release-checks
  cmake --build --preset release-checks
  ctest --preset release-checks

  cmake --preset sanitizer-checks
  cmake --build --preset sanitizer-checks
  ctest --preset sanitizer-checks

AddressSanitizer, UndefinedBehaviorSanitizer, and float-cast-overflow checks
are enabled together. Leak detection is disabled in the sandbox preset because
LeakSanitizer cannot reliably inspect threads under restricted process tracing;
this does NOT disable address or undefined-behavior checks. For an unrestricted
host, run CTest directly with ASAN_OPTIONS=detect_leaks=1 if leak coverage is needed.

Physical audio-device checks remain separately selectable:

  ctest --test-dir build-release-checks -L hardware --output-on-failure

They can return skip code 77 when no usable device is available. Offscreen checks
do not establish real speaker/capture behavior. Do not run performance benchmarks
alongside other heavy tests when comparing timing results.

Fixtures
--------

tests/support/VDQtTestFixtures supplies small CFR/silent MP4 and built-in AVS
clips; VFR, unknown-count H.264, repeated timestamps, longer/shorter audio, high
bit depth, alpha/padded-row images, PNG sequences, nested/misnamed manifests,
and an invalid filesystem destination. The controller baseline smoke-decodes
edge-case media without asserting currently broken timeline/safety semantics.
Their detailed behavioral assertions belong with the corresponding repair batch.

Performance baseline
--------------------

  build-release-checks/application_baseline_tests --benchmark 8 \
      --report build-release-checks/baseline.json

Longer-source comparison (same resolution, ten times as many frames):

  build-release-checks/application_baseline_tests --benchmark 2 --frames 480 \
      --report build-release-checks/long-source-baseline.json

Reports contain per-cycle source-open, sequential decode, random-scrub, and
complete ProRes export timings, fps, resident memory, thread count, and test
directory size. Outputs are removed after each cycle. RSS includes allocator
high-water retention; an increase alone does not prove leaked live objects.
Export timings include encoder startup/pipe/finalization, not just encode CPU.

The session benchmark uses one real decoder/exporter repeatedly, a synthetic
1080p MP4, and AVS BlankClip with no plugins or audio. The separate offscreen test
exercises the real MainWindow/preview worker. Neither replaces profiling the
user's AVS plugin chain and audio path or proves the cause of a real-world slowdown.

Initial observations before the filter repair, 2026-10-02:
  - Release checks: 8 passed; physical-audio test excluded.
  - Eight alternating 48-frame sessions: ProRes 84.7-92.5 fps.
  - Threads remained 29; test disk usage remained approximately 4.34 MB.
  - RSS rose from approximately 183 MiB to 343 MiB. This warrants follow-up;
    the user's repeated 30% throughput loss was not reproduced by this fixture.
  - Raw measurements are in the ignored build directory, baseline-before.json.

Filter-memory guardrails
------------------------

  ctest --preset sanitizer-checks -R filter_memory

Each of Temporal Smoother, Inverse Telecine, Television, and Warp Sharp is tested
in a separate process. Small serial images and 1080p/4K parallel images use odd
RGB strides, alpha, temporal history, retained output aliases, and opacity
snapshots. Whole-frame pixels are compared to a scalar reference; null/failed
phase sequences must report failure with no partial outputs. High-depth tests
preserve existing behavior without claiming to implement missing algorithms.
Duplicating Bob chains also verify independent temporal state for both phases.

A single-CPU host can check pixels but cannot exercise the multi-worker race.
Do not turn this memory-safety repair into a field-history, IVTC cadence, or
high-depth feature rewrite: those findings have their own planned batches.

Linux Release builds also run four filter_allocation tests. Each limits only its
own disposable test process's address space, forcing a real QImage-detachment
allocation failure, then restores the budget and verifies successful recovery.
These are intentionally excluded from ASan builds because ASan reserves large
shadow-memory mappings. No production allocation limit or test hook is added.

Repair validation, 2026-10-02:
  - Before repair, all four audit probes reproduced heap-use-after-free. The new
    tests also failed on corrupted parallel pixels or the same sanitizer error.
  - After repair, scalar-reference pixel, source/output ownership, alpha,
    high-depth-preservation, seek-discontinuity, and failed-sequence checks pass
    at 1080p/4K with eight available workers in both Release and sanitizer builds.
  - The four real allocation-failure/recovery tests pass in Release.
  - Full selected suites: Release 16/16 passed; sanitizer 12/12 passed. Physical
    audio-device checks are excluded, and allocator-limit checks run only in Release.

Source lifetime and operation isolation (H06/H07)
------------------------------------------------

  ctest --preset release-checks -R 'operation_|plugin_host_tests'
  ctest --preset sanitizer-checks -R 'operation_|plugin_host_tests'

operation_source repeatedly switches built-in AVS clips with audio and silent
MP4s, queues Open during Close, coalesces competing Opens during window sizing,
and rapidly starts/stops playback. Close must not dispatch a new Open midway
through releasing its consumers. The physical audio sink remains disabled.

operation_snapshot changes both the caller's request and the editable filter
chain inside export callbacks. Raw and lossless video output must retain the
captured range and pixels throughout the operation.

operation_audio verifies an explicit offline audio-filter snapshot and the
default snapshot across multiple extracted ranges. Changing the editor/caller
chain inside progress callbacks must not change the captured mute or sample
count. Synthetic WAVs are used, with playback-device creation disabled.

operation_queue invokes Open, Close, script execution, edit/filter controls,
queue reload, and nested export entry points while a real queued render runs.
The editor must remain unchanged while job-specific settings determine output.
Abort must remain callable, leave no completed output, and restore usable menus,
transport controls, and source opening. The native plugin test additionally
counts live test-module instances to verify private pipeline ownership, scoped
reset, and destruction without changing the serialized filter IDs.

Long operations now stop/join preview work before borrowing an interactive
source, use scoped editor ownership, and retain Job Control/progress controls.
Queued video/raw/image rendering owns its filter pipeline; offline audio uses
an explicit filter snapshot and does not create a playback sink. Closing a
source releases preview/worker runtime caches while preserving session options.

These checks do not establish the cause of the user's progressive ProRes export
slowdown or validate arbitrary third-party AVS/VDX plugins. See the following
checkpoints for H08/H09 and dependency discovery/scaling (S02/S12).

Validation of this checkpoint, 2026-10-02:
  - Release: 20/20 selected checks passed; sanitizer: 16/16 passed.
  - Export error dialogs remain keyboard-accessible while editor input is locked.
  - Physical audio-device checks are excluded; the codec troubleshooting suite
    is not included. Leak detection remains disabled as described above.
  - Eight alternating 1080p MP4/AVS/ProRes cycles: 87.1-92.2 fps, 29 threads.
    RSS rose from approximately 182 MiB to 334 MiB; unchanged test disk usage
    was approximately 4.34 MB. This is not proof of a leak or its absence.
    The observed progressive 30% throughput loss still was not reproduced.
  - Raw measurements: build-release-checks/isolation-after.json (ignored).
  - The regular build/VirtualDubQt is rebuilt and passes the VCF smoke check.

Numbered output approval and recoverable replacement (H08/H09)
-------------------------------------------------------------

  ctest --preset release-checks -R 'output_transaction_tests|operation_outputs'
  ctest --preset sanitizer-checks -R 'output_transaction_tests|operation_outputs'

output_transaction_tests contains 23 disposable-filesystem scenarios: fresh and
approved output, denied approval, late collisions, changed/replaced files,
invalid staging, duplicate/hardlinked targets, directory targets, dangling
symlinks, changed containing directories, backup/commit/removal/restore failures,
unsupported atomic moves, racing collisions during moves/rollback, exception
unwinding, and invalid destinations inside staging. Failure injection overrides
only narrow filesystem methods. No user media or user process is involved.

Recovery tests verify retained backups and recovery maps AFTER destruction of
the QTemporaryDir that formerly deleted the only surviving originals. A foreign
file occupying a destination must survive rollback untouched. Successful rollback
restores originals; successful commit preserves normal permissions and cleanup.

operation_outputs exercises the real controller and dialogs: unattended segmented
AVI must reject numbered-file collisions even when the selected base name is new;
Cancel preserves originals; Yes installs decodable segments; changes inside the
approval dialog invalidate approval. It also checks unattended script images,
denied/approved queued image replacement, and a file appearing during rendering.

The common transaction is used for AVI segments, all three image-sequence entry
points, and split capture. Physical capture remains untested without a device.
Single-file atomic replacement does not use these multi-file backups. This batch
does not repair the unreproduced progressive AVS/ProRes slowdown. Dependency
discovery/scaling (S02/S12) is covered by the following checkpoint.

Validation of this checkpoint, 2026-10-02:
  - Release: 22/22 selected checks passed; sanitizer: 18/18 passed.
  - All 23 filesystem scenarios pass in both builds, as do real-controller
    approval, cancellation, concurrent-change, and queued-image checks.
  - Physical audio/capture devices are not exercised. Allocator-limit tests run
    only in Release; the separate codec troubleshooting suite remains excluded.
  - build/VirtualDubQt is rebuilt and passes the generated VCF smoke check.

Recursive source protection and bounded audit scaling (S02/S12)
-------------------------------------------------------------

  ctest --preset release-checks -R 'source_safety_|operation_safety'
  ctest --preset sanitizer-checks -R 'source_safety_|operation_safety'
  build-release-checks/source_safety_tests --scaling-test

source_safety_tests uses disposable files to check content-detected, misnamed,
and nested manifests, literal imports with unusual extensions, multiple/named
imports, exact concat quoting, ordered/repeated timeline entries, hardlinks,
symlinks, physical symlink/../ traversal, aliases with different relative-path
contexts, source identity replacement, changed manifests, cycles, recursion/work
limits, missing/binary/oversize documents, remote protocols, Python imports, and
dynamic scripts. Incomplete graphs must refuse unrelated existing destinations
without rejecting unrelated new destinations. No scripts or user files are run.

source_safety_scaling creates 1,000 and 8,000 synthetic image-source paths. It
checks 8,000 output paths against a single captured snapshot and verifies that
the read counters do not change. One precommit refresh must perform exactly one
additional dependency walk. Reported timings are observations, not portable
pass/fail thresholds; the counters include small header probes.

operation_safety uses real decoders, exporters, automation, and queue validation.
Raw/video exports from list.txt and a three-layer concat chain cannot replace
their MP4 source. Unrelated raw outputs remain usable. A manifest changed during
rendering must protect newly referenced media at commit while retaining the old
source. GUI/queue paths reject dependency aliases; audio automation protects
misnamed-manifest inputs and borrowed AVS source scripts, while an ordinary WAV
export remains functional through the new staging path.

Snapshots are operation-scoped, not a session-long cache. Each snapshot collects
sources at capture and refreshes before commit, with hash-based destination
checks between them. This addresses image-sequence safety overhead, not the reported
progressive 30% AVS/ProRes throughput loss, which remains unreproduced and open.
Physical capture/audio devices and arbitrary third-party script/plugin graphs
are not exercised; this is not a filesystem-locking guarantee.

Validation of this checkpoint:
  - Release: 25/25 selected checks passed; sanitizer: 21/21 passed.
  - Observed Release capture time was approximately 12 ms for 1,000 source
    images and 98 ms for 8,000. Checking 8,000 destinations took approximately
    22-24 ms at either source count, with no additional source reads.
    These observations are not a guarantee for other storage or workloads.
  - Physical audio-device checks are excluded; allocator-limit checks run only
    in Release. The codec troubleshooting suite remains outside these targets.
    Sanitizer leak detection remains disabled as documented above.
  - The regular build/VirtualDubQt is rebuilt and passes the generated VCF
    smoke check under isolated configuration/data directories.
